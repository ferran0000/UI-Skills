# Module: Interaction, Forms, States & Ethics (`mod-interaction-forms`)

対象: ボタン、ナビゲーション、フォーム、Webアプリの状態遷移

## 1. アクション階層と操作性
- **D-1 アクション3階層ルール**:
  - **Primary（主行動）**: **1ビューポート（または1セクション）につき原則1つ**。塗りつぶし高コントラストボタン。
  - **Secondary（副行動）**: アウトラインまたは低コントラスト背景。
  - **Tertiary（補助行動）**: テキストリンク風。
- **D-2 ターゲットサイズ基準**:
  - 最低基準（WCAG 2.2 SC 2.5.8 AA）: **24×24px 以上**（または隣接ターゲットとの間隔含め24px確保）。
  - 推奨（Apple HIG / モバイル主要操作）: **44×44px 以上**（Android/Materialは 48dp）。
- **D-3 危険操作の隔離と可逆性**:
  - 削除・解約・課金確定などの破壊的／不可逆操作は Primary ボタンから物理的に離し、確認ダイアログまたは Undo（取り消し）を必須とする。
- **D-5 選択肢の整理（ヒックの法則）**:
  - 選択肢が多い場合は闇雲に削るのではなく、意味のあるカテゴリへの**チャンク化**と**段階的開示（Progressive Disclosure）**で認知負荷を下げる。

## 2. フォーム設計とエラー回復
- **E-1a 必須・任意の明示**: 必須項目と任意項目を視覚・テキスト両面で明確に区別する。
- **E-1b 低頻度項目の格納**: 住所2行目やクーポンコードなど一部ユーザーしか使わない項目は、リンクやアコーディオンの背後に隠す。
- **E-2 入力幅のヒント化**: 郵便番号・年・CVVなどは期待される文字数に合わせた入力欄幅にする。
- **E-3 ポステルの法則**: ハイフン有無・全角半角・前後スペースの揺れでエラーを出さず、システム側で正規化する。
- **E-4 入力データの保持**: バリデーションエラー時にユーザーの入力済み内容を絶対に消去しない。
- **E-5 具体的なエラーメッセージ**: 「入力が不正です」は禁止。「何が要件で、現在どうズレているか、どう直せばよいか」を具体提示し、最初のエラー要素へフォーカスを移す。
- **E-6 ラベル常時表示**: `placeholder` をラベル代わりにしない。`<label for="...">` を入力欄の上に常時固定表示する。

## 3. 5つのUI状態とレスポンス時間
- **F-1 5状態の網羅設計**:
  1. **Ideal（正常表示）**
  2. **Loading（読み込み中）**: 1秒超の処理ではスケルトンまたは進捗バーを表示
  3. **Empty（空状態）**: 初回利用・0件時に「次に何をすべきか」の導線（CTA）を置く
  4. **Error（エラー）**: 原因と復旧アクション（再試行・戻る）を提示
  5. **Success（完了）**: 明確な達成フィードバックと次の導線（ピーク・エンドの法則）
- **F-2 レスポンス時間基準（NN/g & ドハティのしきい値）**:
  - **~100ms (0.1秒)**: ボタン押下・ホバー等の即時フィードバック（アクティブ状態変化）。
  - **~400ms**: 対話フローを維持できるしきい値（ドハティのしきい値）。
  - **1秒超**: ローディング表示を出す（1秒未満の高速処理で毎回スケルトンを出すと画面がちらつくため避ける）。
  - **10秒超**: 進捗率（%）とキャンセル手段を表示。

## 4. マイクロコピーとダークパターン回避
- **F-4 動詞ベースのボタン文言**: 「OK」「はい」「送信」ではなく、結果が予測できる動詞にする（例: `変更を保存する`、`アカウントを削除する`）。
- **F-5 ダークパターン禁止（権威順序1位）**:
  - 確認シェイミング（「いいえ、お得を諦めます」等）禁止。
  - 解約・退会・オプトアウトを登録より意図的に難しくする設計（Roach Motel）禁止。
  - 偽のカウントダウンや根拠のない緊急表示の禁止。
