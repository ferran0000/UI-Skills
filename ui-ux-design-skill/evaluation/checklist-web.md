# Evaluation Checklist: Web & UI (`checklist-web`)

Phase 3 でのみロードする。全観点を「機械判定」「LLM原則判断」「未検証」の3区分で評価する。

## 区分1: 機械判定（`scripts/ui_ux_checker.py` または静的計算）
- [ ] **M-W1 コントラスト比**: テキスト（4.5:1 / 大文字3.0:1）および非テキストUI（3.0:1）が WCAG 2.2 AA を満たすか。（`B-03`）
- [ ] **M-W2 ターゲットサイズ**: インタラクティブ要素が 24×24px 以上（主要タップ対象は 44×44px 推奨）か。（`D-2`）
- [ ] **M-W3 フォーカスリング保護**: `:focus` / `:focus-visible` で `outline: none` の単独指定がないか。（`B-05`）
- [ ] **M-W4 セマンティック＆属性**: `<img>` の `alt` 付与、フォーム入力と `<label>` の紐付け、見出しレベル連続性。（`B-04`, `B-05`, `B-07`）
- [ ] **M-W5 汎用リンク文言の排除**: 「こちら」「詳細」「クリック」のみのリンクが存在しないか。（`B-7`）
- [ ] **M-W6 トークン準拠（既存DSがない新規生成時）**: 任意の hex / 恣意的な px 直書きを避け、トークン変数を使用しているか。（`A-6`）

## 区分2: LLM原則判断（6大原則に基づく証拠付き評価）
- [ ] **P-1 認知負荷の最小化**: タイトル・冒頭要素・Primaryボタンから、目的と次の行動が迷わず読み取れるか。1ビューポートに Primary が乱立していないか。（`B-01`, `D-1`）
- [ ] **P-2 一貫性と慣習の尊重**: 既存DSや一般的なWeb慣習（ヤコブの法則）を裏切る独自操作がないか。同じ機能に同じ見た目・言葉が使われているか。
- [ ] **P-3 状態の可視性とフィードバック**: Ideal / Loading / Empty / Error / Success の必要状態が設計されているか。1秒超の処理へのフィードバック方針があるか。（`F-1`, `F-2`）
- [ ] **P-4 エラー防止と可逆性**: 破壊的操作が隔離され、確認または Undo があるか。エラー文言は具体的で入力値を保持するか。（`B-02`, `B-04`, `E-5`）
- [ ] **P-5 視覚階層と近接関係（コード構造上）**: 色を抜いてもサイズ・太さ・余白で階層が成立する設計か。グループ間余白 ＞ グループ内余白になっているか。（`A-1`, `A-4`）
- [ ] **P-6 倫理とユーザー主導権**: ダークパターンがなく、戻る・キャンセル・停止がいつでもできるか。（`B-06`, `F-5`, `AI-1`）

## 区分3: 未検証（コードだけでは判定不可 — 必ず明示する）
※ ヘッドレスブラウザによるスクリーンショット確認や実機テストを行っていない場合、以下は合格とせず `未検証` として報告する。
- [ ] **U-W1 実レンダリングでの視覚階層・バランス**: 実際の画面上で視線が意図通り誘導されるか、意図しない折り返し・要素重なりがないか。
- [ ] **U-W2 実測パフォーマンス・体感速度**: 実環境での応答時間（100ms / 1秒基準）やスクロールの滑らかさ。
- [ ] **U-W3 実機・支援技術検証**: モバイル実機での片手操作性、スクリーンリーダーでの読み上げ順。
