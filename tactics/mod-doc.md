# Module: Document & Japanese Typography (`mod-doc`)

対象: Markdown文書、仕様書、技術ドキュメント、ヘルプ記事、Web記事本文

## 1. 情報構造とスキャナビリティ（NN/g 準拠）
- **DOC-01 レイヤーケーキ構造**: 読者が見出しだけを追って目的の箇所へ到達できるよう、連続した見出し階層（`h1` → `h2` → `h3`）で骨格を作る。
- **DOC-02 逆ピラミッド構造**: 文書全体でも各セクションでも、結論・要約・最重要アクションを冒頭（最初の1〜2段落）に置く。
- **DOC-03 先頭キーワード配置**: 見出し・箇条書きは先頭（日本語なら最初の1〜2文節・10文字以内）に情報価値の高い主語やキーワードを置き、縦の視線移動だけで内容を判別できるようにする（例: `×: 導入にあたっての注意事項について` → `○: 導入前の確認事項`）。
- **DOC-04 段落設計（文脈別の最適化）**:
  - **一般文書・Web記事・ガイド**: 1段落 1 トピック・3文以内（目安120〜180字）で簡潔に区切る。
  - **仕様書・法務・マニュアル**: 網羅性と厳密性を保ちつつ、表・箇条書き・コールアウト・折りたたみを用いて視覚的にチャンク化する（チェッカー実行時は `--doc-type spec` を指定）。

## 2. 日本語タイポグラフィ（HTML/CSS 制御可能な場合）
※ 純粋な Markdown のみ出力する場合は以下をスキップし、見出し・箇条書き・表の構造化に集中する。
- **DOC-05 行間・文字サイズ・1行文字数**:
  - 本文サイズ: 最低 `14px`、標準 `16px` 以上。
  - 日本語行間（デジタル庁デザインシステム準拠）: 標準 `line-height: 1.7`（170%）、心理的負荷を抑えたい長文は `1.75`（175%）、最小 `1.6`。CSSでは単位なし数値で指定する。
  - 1行あたり文字数: PCで **35〜45文字**（`max-width: 42em` 程度）、モバイルで **20〜25文字**。
- **DOC-08 日本語組版の配慮**:
  - 可読性の高い日本語ゴシック体（`BIZ UDPGothic`, `Hiragino Kaku Gothic ProN`, `Noto Sans JP`）をフォールバック含め指定する。
  - **英数字は半角、和文の約物（「」、。！？：）は全角**に統一する。

### Good Pattern: 日本語長文のタイポグラフィCSS
```css
.prose-ja {
  font-family: var(--font-ja);
  font-size: var(--text-base);
  line-height: 1.75;
  max-width: 42em;
  text-align: left;
}
```

## 3. 強調・配置・リンクテキスト（NN/g & W3C WAI 準拠）
- **DOC-06 強調と配置**:
  - 本文は左揃えで視線の開始位置を揃える。
  - 太字は流し読み時に意味の骨格（scannable skeleton）を作るため、各段落で最も重要なフレーズの断片だけに絞って適用する。
  - 下線はハイパーリンクの識別に専用で割り当てる。段落の区切りは段落間余白で統一する。
- **DOC-07 自己完結したリンクテキスト**:
  - リンクテキストは「クリックしたら何が得られるか」を文脈なし（リンク一覧で読み上げられた状態）でも単体で理解できる表現にし、先頭を情報価値の高いキーワードから始める（例: `料金プランの比較表を見る`）。
  - 本文中のリンクは下線または明確なアイコンで周囲のテキストと視覚的に区別する。
