# Module: Document & Japanese Typography (`mod-doc`)

対象: Markdown文書、仕様書、技術ドキュメント、ヘルプ記事、Web記事本文

## 1. 情報構造とスキャナビリティ（NN/g 準拠）
- **B-1 レイヤーケーキ構造**: 読者が「見出しだけを追って目的の箇所へ飛べる」ように、明確な見出し階層（`h1` → `h2` → `h3`、スキップ禁止）を設計する。
- **B-2 逆ピラミッド構造**: 文書全体でも各セクションでも、結論・要約・最重要アクションを冒頭（最初の1〜2段落）に置く。
- **B-3 先頭2語ルール**: 見出し・箇条書きは前置きを避け、情報価値の高いキーワードから書き始める。
- **B-4 短文と1段落1アイデア（例外規定付き）**:
  - 一般文書・Web記事・ガイド: 1段落 1 トピック・3文以内（目安120〜180字）を基本とする。
  - **例外（仕様書・法務・マニュアル）**: 網羅性・厳密性が優先される場合は無理に削らず、表・箇条書き・コールアウト・折りたたみで視覚的にチャンク化する。

## 2. 日本語タイポグラフィ（HTML/CSS 制御可能な場合）
※ 純粋な Markdown のみ出力する場合は以下をスキップし、見出し・箇条書き・表の構造化に集中する。
- **B-5 行間・文字サイズ・1行文字数**:
  - 本文サイズ: 最低 `14px`、推奨 `16px` 以上。
  - 日本語行間（デジタル庁デザインシステム準拠）: 標準 `line-height: 1.7`（170%）、心理的負荷を抑えたい長文は `1.75`（175%）、最小 `1.6`。CSSでは単位なし数値で指定する。
  - 1行あたり文字数: PCで **35〜45文字**（`max-width: 42em` 程度）、モバイルで **20〜25文字**。
- **B-8 日本語組版の配慮**:
  - フォント指定は可読性の高い日本語ゴシック体（例: `BIZ UDPGothic`, `Hiragino Kaku Gothic ProN`, `Noto Sans JP`）をフォールバック含め指定する。
  - 全角英数字を混ぜず、英数字・記号は半角に統一する。

## 3. 組版の節度（Practical Typography 準拠）
- **B-6 装飾の抑制**:
  - 下線はハイパーリンク以外で使わない。
  - 太字と斜体を重ねない。強調（太字）は1段落に1〜2箇所まで。
  - 長文の中央揃えは禁止（左揃えを徹底）。
  - 段落区切りは「段落間余白」のみとし、字下げと併用しない。
- **B-7 意味のあるリンクテキスト**:
  - 「こちら」「詳細」「クリック」「リンク」などの汎用文言を禁止。遷移先の内容がリンク単体で分かる名詞・動詞句にする（例: `料金プランの比較表を見る`）。
