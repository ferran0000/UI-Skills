# Module: Interaction, Forms, States & Ethics (`mod-interaction-forms`)

対象: ボタン、ナビゲーション、フォーム、Webアプリの状態遷移

## 1. アクション階層と操作性
- **INT-01 アクション3階層ルール**:
  - **Primary（主行動）**: **1ビューポート（または1セクション）につき原則1つ**。塗りつぶし高コントラストボタン。
  - **Secondary（副行動）**: アウトラインまたは低コントラスト背景。
  - **Tertiary（補助行動）**: テキストリンク風。
- **INT-02 ターゲットサイズ基準**:
  - 最低基準（WCAG 2.2 SC 2.5.8 AA）: **24×24px 以上**（または隣接ターゲットとの間隔含め24px確保）。
  - 推奨（Apple HIG / モバイル主要操作）: **44×44px 以上**（Android/Materialは 48dp）。
- **INT-03 危険操作の隔離と可逆性**:
  - 削除・解約・課金確定などの破壊的／不可逆操作は Primary ボタンから物理的に離し、確認ダイアログ（対象名や件数を明示）または Undo（取り消し）を必ず備える。
- **INT-04 選択肢の整理と操作代替（ヒックの法則 / WCAG 2.2 SC 2.5.7）**:
  - 選択肢が多い場合は意味のあるカテゴリへの**チャンク化**と**段階的開示（Progressive Disclosure）**で判断負荷を下げる。
  - ドラッグ操作（並び替え・スライダー等）を使う場合は、シングルポインター（上下移動ボタン・数値入力等）の代替手段を併設する。

## 2. フォーム設計とエラー回復（GOV.UK / NN/g / WCAG 2.2 準拠）
- **INT-05 必須・任意の明示と低頻度項目の整理**:
  - ほとんどの項目が必須のフォームでは「（任意）」を明記する（GOV.UK方式）、または必須と任意が混在する場合は両方を明確に区別する。
  - 住所2行目やクーポンコードなど一部ユーザーしか使わない項目は、リンクやアコーディオンの背後に整理する。
- **INT-06 入力幅のヒント化・ポステルの法則・冗長入力回避（SC 3.3.7）**:
  - 郵便番号・年・CVVなどは期待される文字数に合わせた入力欄幅にする。
  - ハイフン有無・全角半角・前後スペースの揺れはシステム側で吸収・正規化して受け入れ、同一プロセス内で既に入力済みの情報を再入力させない。
- **INT-07 入力データの保持（ハードガードレール）**: バリデーションエラーや通信失敗時でも、ユーザーの入力済み内容をフォーム上に保持し続ける（入力値リセット禁止）。
- **INT-08 エラーメッセージと検証タイミング**:
  - **タイミング**: 入力途中ではなく、フォーカスアウト（`onBlur`）または送信時に検証する。
  - **内容とトーン**: ラベルと同じ語句を含め、「何が起きたか」と「どう直せばよいか」を平易・肯定的に書く（未入力は「メールアドレスを入力してください」、制限超過は「ユーザー名は35文字以内で入力してください」）。
  - **配置とフォーカス**: フォーム上部に Error Summary（`role="alert"` またはフォーカス移動）を置き、各エラー欄の直前にも同じ文言と `border-input` 以上の視認性ある赤枠を配置する（インラインエラーには二重読み上げを防ぐため `role="alert"` を付けない）。
- **INT-09 ラベルと常時表示ヒントテキストの分離**:
  - すべての入力欄の直上に短く直接的な `<label for>` を常時表示する。
  - 入力形式の例や利用目的の補足は、ラベルと入力欄の間に **常時表示される短い1文のヒントテキスト（`aria-describedby` で紐付け）** を配置する。

## 3. 5つのUI状態とレスポンス時間
- **INT-10 5状態の網羅設計**:
  1. **Ideal（正常表示）**
  2. **Loading（読み込み中）**: 1秒超の処理ではスケルトンまたは進捗バーを表示
  3. **Empty（空状態）**: 初回利用・0件時に「次に何をすべきか」の導線（CTA）を置く
  4. **Error（エラー）**: 原因と復旧アクション（再試行・戻る）を提示
  5. **Success（完了）**: 処理成功の報告に加え、「次に何が起きるか（いつ・誰が対応するか／次の推奨アクション）」を伝える
- **INT-11 レスポンス時間基準（NN/g & ドハティのしきい値）**:
  - **~100ms (0.1秒)**: ボタン押下・ホバー等の即時フィードバック。
  - **~400ms**: 対話フローを維持できるしきい値（ドハティのしきい値）。
  - **1秒超**: ローディング表示を出す（1秒未満の高速処理では画面ちらつきを防ぐためスケルトンを出さず結果を表示する）。
  - **10秒超**: 進捗率（%）とキャンセル手段を表示。

## 4. マイクロコピーと倫理（GOV.UK / NN/g 準拠）
- **INT-12 動詞＋目的語のボタン文言とダークパターン禁止（ハードガードレール／権威順序1位）**:
  - ボタン文言は押した結果の約束を明示する **「具体的な動詞＋目的語」** にし、不可逆操作は対象件数や結果まで明記する（例: `変更を保存する`、`3件のファイルを削除する`）。
  - 確認シェイミング、解約・退会の意図的妨害（Roach Motel）、偽のカウントダウンや根拠のない緊急表示を禁止する。
