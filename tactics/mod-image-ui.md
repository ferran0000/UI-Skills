# Module: Image UI Mockups & Screenshot Review (`mod-image-ui`)

対象: JPEG / PNG 形式のアプリ画面案、UIモックアップ画像生成、既存スクリーンショット・デザインカンプの視覚レビュー

## 1. 画像生成前のUI骨格設計（プロンプト設計戦術）

- **IMG-01 画面比率とセーフエリアの明示**:
  - 対象デバイスに応じてアスペクト比を最初に固定する（モバイル: `9:16`、タブレット: `4:3`、デスクトップWeb: `16:9`）。
  - モバイル画面では上部のステータスバー領域と下部のナビゲーション／ホームインジケータ領域に十分な余白を確保し、重要ボタンを端へ寄せすぎない。
- **IMG-02 要素数の制限と1ビューポート1主行動**:
  - 画像生成モデルは情報過多になるとグリッドや文字が崩れやすいため、1画面内の主要情報ブロックは **3〜4個** に整理する。
  - Primary CTA（主行動ボタン）は **画面内に1つ** に絞り、「ヘッダー／タイトル → 核心コンテンツ → Primary CTA」の視覚階層をプロンプト内で明確に順序付ける。
- **IMG-03 検証済み配色のプロンプト指定**:
  - 既存DSやブランドカラー指定がない場合は、`tokens/design-tokens.json` の配色（ライト: 背景 `#FFFFFF`・サーフェス `#F8FAFC`・文字 `#0F172A`・主行動 `#1D4ED8` / ダーク: 背景 `#0F172A`・サーフェス `#1E293B`・文字 `#F8FAFC`・主行動 `#93C5FD`）を役割ごとに明記する。
  - フラットまたは控えめなシャドウでサーフェス階層を表現し、視認性を損なう過度なグラデーションや背景写真上の直置きテキストを避ける。
- **IMG-04 テキスト崩れ対策とマイクロコピー**:
  - 画面内テキストは短く具体的な見出し・ラベル・動詞＋目的語のボタン文言（例: `予約を確定する`）に絞る。
  - 長文説明が必要な領域は、生成時の文字化けを防ぐため短い1〜2行の要約文または整理されたリスト形式に留める。

## 2. 生成画像・既存スクリーンショット共通の視覚品質基準

- **IMG-05 近接の法則と余白バランス**: 関連要素間の余白よりグループ間の余白が明確に広いこと（2倍以上目安）。
- **IMG-06 視覚的コントラストと非色手がかり**: テキスト・アイコン・入力欄境界が背景から十分に識別でき、ステータスや優先度が色だけでなく太字・サイズ・アイコン・配置で判別できること。
- **IMG-07 生成アーティファクトの排除（画像生成時）**: 読めない文字化け、意図しないテキスト見切れ、不自然な二重ボーダー、要素の重なり、意味不明なアイコンが混入していないこと。
- **IMG-08 静止画レビューの境界明示**: JPEG / PNG 単体からはセマンティックHTML、キーボード操作、スクリーンリーダー読み上げ、実機上の物理タップサイズ、エラー時の入力保持などは判定できない。視覚確認・ピクセル計測できた範囲のみを根拠とし、判定不能項目は必ず未検証（`UNV-I1`〜`UNV-I3`）として報告する。
