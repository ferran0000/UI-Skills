# Evaluation: Blocker Definitions, Coverage & Severity Rules

Phase 3 の自己評価で「修正ループを必須発動させる致命的欠陥（Blocker）」を具体項目として定義する。
**以下の `BLK-01`〜`BLK-07` に該当する場合のみ Blocker とする**。

## 1. Blocker リストと機械判定カバレッジ表

| ID | 対象 | 欠陥の具体定義 | 機械判定カバレッジ | 機械判定の限界（LLM/未検証で補完） |
| :--- | :--- | :--- | :--- | :--- |
| **BLK-01** | Web / 文書 | **主要アクション／結論の不在**: 画面・文書の冒頭を見ても「何の画面／文書か」「次に何をすべきか」が特定できない。 | LLM判断のみ | 意味理解が必要なため機械判定不可 |
| **BLK-02** | Web | **不可逆操作の無防備**: 削除・解約・課金確定などの破壊的操作に、確認ステップも Undo もなく、Primary と同等の位置・見た目で誤爆しやすい。 | LLM判断のみ | 操作の破壊性・導線意図の判定が必要 |
| **BLK-03** | Web | **コントラスト比 WCAG 2.2 AA 未満**: 通常テキスト 4.5:1 未満、大文字 3.0:1 未満、UI境界・アイコン 3.0:1 未満。 | **一部可** | 同一ルール内の色ペア・ローカル外部CSS・テーマ別変数・rgba合成を検査。継承カスケード・画像上テキスト・JSX/Tailwindはスキップ（`coverage` に出力） |
| **BLK-04** | Web | **フォーム入力データの消失／ラベル欠落**: エラー時に入力値をリセットする設計、または `<label>` / `aria-label` 欠落。 | **一部可** | HTML上のラベル欠落は機械検出。エラー時リセット挙動はJS/LLM判断 |
| **BLK-05** | Web | **キーボード・アクセシビリティ破綻**: フォーカス消失、非セマンティッククリック要素・キー操作ハンドラ欠如、重要画像の `alt` / リンクのアクセシブルネーム欠落、モーダルのフォーカストラップ欠如。 | **一部可** | 静的HTML/CSSの欠陥は機械検出。モーダル動的挙動・タブ順はLLM/実機確認 |
| **BLK-06** | Web / 文書 | **ダークパターン／虚偽誘導**: 確認シェイミング、意図的な解約妨害、根拠のない偽の緊急表示が含まれる。 | LLM判断のみ | 文言・UI意図の倫理判定が必要 |
| **BLK-07** | 文書 / Web | **見出し構造の破綻**: 見出しレベルがスキップ（`h1`→`h3` 等）している、またはページ開始見出しが `h3` 以降になっている。 | **機械判定可** | HTML/Markdown の見出し階層を機械検出（※壁テキストは Major `CHK-D2` へ分離） |

## 2. 重大度区分と対応ルール

- **Blocker**: リリース不可。Phase 3 の修正ループ（最大2回）で解消する。2回で解消できない場合は理由を明記してユーザーへエスカレーション。
- **Major**: 体験を大きく損なう欠陥（例: タップ領域不足 `CHK-W2`、壁テキスト `CHK-D2`、汎用リンク文言 `CHK-W5`/`CHK-D3`、エラー文言が曖昧、余白の近接関係が逆転、5状態のうち Error/Empty が未設計）。原則修正するが、既存DSや仕様書等の正当な理由があれば理由を明記して残すことも可。
- **Minor**: 改善するとさらに良くなる点（例: トークン外 hex の統一 `CHK-W6`、装飾の節度 `CHK-D4`、マイクロコピーの磨き込み）。修正は任意。

## 3. 証拠義務フォーマット（必須・`review-log.md` 記録形式）
全観点を探索し、合格（Pass）にも欠陥（Blocker/Major/Minor）にも以下の根拠を付記する。

```markdown
- **[判定: Pass / Blocker / Major / Minor / 未検証] 観点ID**
  - **対象**: （セレクタ / 行番号 / 見出し名）
  - **根拠**: （実際のCSS値、HTML属性、抜粋テキスト、または機械判定出力）
  - **影響（欠陥時）**: （どのようなユーザーがどの場面で困るか）
  - **修正方針（欠陥時）**: （最小限かつ安全な修正内容）
```
