# Evaluation: Blocker Definitions & Severity Rules

Phase 3 の自己評価で「修正ループを必須発動させる致命的欠陥（Blocker）」を具体項目として定義する。
原則単位の曖昧な不合格判定は禁止し、**以下の B-01〜B-07 に該当する場合のみ Blocker とする**。

## 1. Blocker リスト（1件でも該当すれば修正必須）

| ID | 対象 | 欠陥の具体定義 | 判定区分 |
| :--- | :--- | :--- | :--- |
| **B-01** | Web / 文書 | **主要アクション／結論の不在**: 画面・文書の冒頭を見ても「何の画面／文書か」「次に何をすべきか」が特定できない。 | LLM原則判断 |
| **B-02** | Web | **不可逆操作の無防備**: 削除・解約・課金確定などの破壊的操作に、確認ステップも Undo もなく、かつ Primary 操作と同等の位置・見た目で誤爆しやすい。 | LLM原則判断 |
| **B-03** | Web | **コントラスト比 WCAG 2.2 AA 未満**: 通常テキスト 4.5:1 未満、大文字 3.0:1 未満、またはUI境界・アイコン 3.0:1 未満。 | 機械判定 |
| **B-04** | Web | **フォーム入力データの消失／ラベル欠落**: エラー時に入力値をリセットする設計、または `<label>` がなく `placeholder` のみに依存している。 | 機械判定 + LLM |
| **B-05** | Web | **キーボード・アクセシビリティ破綻**: `outline: none` でフォーカスが消失、クリック要素が非セマンティックな `<div>` のみでキーボード操作不可、重要画像に `alt` 欠落。 | 機械判定 |
| **B-06** | Web / 文書 | **ダークパターン／虚偽誘導**: 確認シェイミング、意図的な解約妨害、根拠のない偽の緊急表示が含まれる。 | LLM原則判断 |
| **B-07** | 文書 | **構造の破綻（壁テキスト／見出し欠陥）**: 長文に見出しや段落分割がなくスキャン不能、または見出しレベルがスキップ（`h1`→`h3`等）している。 | 機械判定 + LLM |

## 2. 重大度区分と対応ルール

- **Blocker**: リリース不可。Phase 3 の修正ループ（最大2回）で必ず解消する。2回で解消できない場合は理由を明記してユーザーへエスカレーション。
- **Major**: 体験を大きく損なう欠陥（例: タップ領域44px未満、エラー文言が曖昧、余白の近接関係が逆転、5状態のうちError/Emptyが未設計）。原則修正するが、既存DSや文脈上の正当な理由があれば「理由を明記して残す」ことも可。
- **Minor**: 改善するとさらに良くなる点（例: マイクロコピーの磨き込み、補助的なショートカット追加）。修正は任意。

## 3. 証拠義務フォーマット（必須）
すべての指摘および合格判定は以下の4要素を揃えて記述する。根拠のない「問題なし」は禁止。

```markdown
- **[判定: Pass / Blocker / Major / Minor / 未検証] 観点ID**
  - **対象**: （セレクタ / 行番号 / 見出し名）
  - **根拠**: （実際のCSS値、HTML属性、抜粋テキスト、または機械判定出力）
  - **影響（欠陥時）**: （どのようなユーザーがどの場面で困るか）
  - **修正方針（欠陥時）**: （最小限かつ安全な修正内容）
```
